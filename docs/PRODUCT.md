# Katana Connector — продукт

## Что это

Katana Connector — одно нативное iOS-приложение, которое даёт веб-приложению Katana (PWA) доступ к функциям устройства, недоступным из браузера.

```
Katana PWA → custom URL scheme → Katana Connector → нативная функция → локальная очередь событий → Katana API
```

PWA открывает Connector по ссылке, пользователь выполняет действие нативно, Connector сохраняет результат в локальную очередь и отправляет его в Katana API, когда есть сеть.

## Исходная точка

Сейчас в репозитории — ScreenshotSweep: SwiftUI-приложение для разбора скриншотов (показ → «оставить» / «на удаление» → undo → проверка → удаление с подтверждением). Без сети, аналитики и сторонних SDK. Эта функция становится первой функцией Connector — **Screenshot Cleanup** — и её поведение не должно меняться при рефакторинге.

## Принципы

1. **Одно приложение, один стабильный Bundle ID.** Не плодим отдельные приложения под функции. Bundle ID фиксируется один раз (KC-002) и после появления Keychain (KC-004) не меняется.
2. **Приватность по умолчанию.** Фото, их превью, метаданные и идентификаторы не покидают устройство. Сервер получает только агрегированные итоги.
3. **Разрешения — по требованию.** Каждое разрешение запрашивается отдельно, после явного действия пользователя в соответствующей функции. Никаких «разрешите всё» на старте.
4. **Надёжная доставка.** События пишутся в persistent-очередь до отправки и доставляются идемпотентно (повторная отправка не создаёт дублей на сервере).
5. **Пользователь контролирует разрушительные действия.** Удаление — только после подтверждения в приложении и системного диалога iOS.
6. **Без сторонних зависимостей.** Только фреймворки Apple.

## Функции

### Обязательные (в порядке появления)

| Функция | Описание | Задачи |
|---|---|---|
| QR pairing | Привязка устройства к аккаунту Katana сканированием QR-кода из PWA | KC-004 |
| Device token в Keychain | Токен устройства, полученный при pairing, хранится только в Keychain | KC-004 |
| Capability registry | Список функций устройства и их состояния (доступна / нет разрешения / не поддерживается) | KC-003, KC-008 |
| Persistent event queue | Локальная очередь событий, переживающая перезапуск и офлайн | KC-005 |
| HTTPS API client | Отправка событий и отчётов в Katana API | KC-005 |
| Custom URL scheme | Точка входа из PWA (открыть функцию, начать pairing) | KC-007 |
| **Screenshot Cleanup** | **Первая законченная функция**: текущий ScreenshotSweep + отправка итогов сессии | KC-006 |
| Capability Lab | Набор независимых ручных probes для проверки возможностей устройства | KC-008 |

### Screenshot Cleanup

- Поведение = текущий ScreenshotSweep (показ, оставить/на удаление, undo, review, удаление с двойным подтверждением).
- По завершении cleanup-сессии в очередь кладётся одно событие `screenshots.cleanup.completed` с полями `viewed`, `kept`, `deleted`, `started_at`, `completed_at` (см. `API.md`).
- В Katana **не** отправляются: изображения, превью, `localIdentifier`, имена файлов, даты скриншотов, размеры, EXIF, геоданные.

### Capability Lab

- Набор **независимых ручных probes**: каждый probe — отдельная кнопка/экран, проверяющий одну возможность устройства (например, камера, геолокация «при использовании», уведомления локальные, Bluetooth и т.п. — конкретный список утверждается в KC-008).
- Probe запускается только вручную; разрешение (если нужно) запрашивается в момент запуска именно этого probe.
- Probes не зависят друг от друга: падение или отказ в разрешении одного не влияет на остальные.
- Результат probe — статус возможности (`available`, `denied`, `unsupported`, `error`) без пользовательских данных; может уходить в capability report.

### Отложено (deferred)

Не реализуются, пока нет отдельного решения в `DECISIONS.md`:

- HealthKit
- Core NFC
- Background location
- App extensions (Share, Widget, Notification Service и т.п.)
- Push-уведомления (APNs)

Причины: требуют entitlements и платного аккаунта разработчика / не работают или работают ограниченно при установке через Sideloadly с бесплатным Apple ID; повышают требования к приватности и ревью.

## Не цели (сейчас)

- Загрузка, синхронизация или бэкап фотографий.
- Аналитика, трекинг, сторонние SDK.
- Публикация в App Store (распространение пока — unsigned `.ipa` из CI + Sideloadly).
- Несколько аккаунтов Katana на одном устройстве (открытый вопрос, см. `DECISIONS.md`).
