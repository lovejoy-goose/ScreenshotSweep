# Katana Connector — продукт

## Что это

Katana Connector — одно нативное iOS-приложение, которое даёт веб-приложению Katana (PWA) доступ к функциям устройства, недоступным из браузера.

```
Katana PWA → custom URL scheme → Katana Connector → нативная функция → локальная очередь событий → Katana API
```

PWA открывает Connector по ссылке, пользователь выполняет действие нативно, Connector сохраняет результат в локальную очередь и отправляет его в Katana API, когда есть сеть.

## Исходная точка

Исходно в репозитории был ScreenshotSweep — SwiftUI-приложение для разбора скриншотов (показ → «оставить» / «на удаление» → undo → проверка → удаление с подтверждением). Без сети, аналитики и сторонних SDK. Эта функция становится первой функцией Connector — **Screenshot Cleanup** — и её поведение не должно меняться при рефакторинге. С KC-002 приложение называется Katana Connector (`app.katana.connector`) и открывается на Dashboard, с которого запускается Screenshot Cleanup.

## Принципы

1. **Одно приложение, один стабильный Bundle ID** — `app.katana.connector` (D-012). Не плодим отдельные приложения под функции. Bundle ID больше не меняется.
2. **Приватность по умолчанию.** Фото, их превью, метаданные и идентификаторы не покидают устройство. Сервер получает только агрегированные итоги.
3. **Разрешения — по требованию.** Каждое разрешение запрашивается отдельно, после явного действия пользователя в соответствующей функции. Никаких «разрешите всё» на старте.
4. **Надёжная доставка.** События пишутся в persistent-очередь до отправки и доставляются идемпотентно (повторная отправка не создаёт дублей на сервере).
5. **Пользователь контролирует разрушительные действия.** Удаление — только после подтверждения в приложении и системного диалога iOS.
6. **Без сторонних зависимостей.** Только фреймворки Apple.

### Screenshot Cleanup

- Поведение = исходный ScreenshotSweep (показ, оставить/на удаление, undo, review, удаление с двойным подтверждением).
- Открывается кнопкой «Разобрать скриншоты» на Dashboard; доступ к фото запрашивается только при входе в функцию.
- По явному завершению разбора в очередь текущего подключения кладётся одно событие `screenshot_cleanup.completed` с полями `session_id`, `started_at`, `completed_at`, `reviewed_count`, `kept_count`, `deletion_requested_count`, `deletion_completed` (см. `API.md`, D-031).
- В Katana **не** отправляются: изображения, превью, `localIdentifier`, имена файлов, даты скриншотов, размеры, EXIF, геоданные.

### Capability Lab

- Набор **независимых ручных probes** (D-034): **Камера** (один кадр, сразу отброшен), **Текущая геолокация** (только «При использовании», одна фиксация, координаты отброшены), **Движение** (одно событие Motion & Fitness, данные отброшены), **Локальные уведомления** (одно нейтральное тестовое уведомление). Открывается кнопкой «Capability Lab» на Dashboard; ссылки на неё нет.
- Probe запускается только вручную; разрешение (если нужно) запрашивается в момент запуска именно этого probe.
- Probes не зависят друг от друга: падение или отказ в разрешении одного не влияет на остальные.
- Результат probe — `probe_state` (`not_run` / `passed` / `failed`) плюс `checked_at` и безопасный код `detail`, без пользовательских данных; сохраняется на iPhone и вместе с `availability` и `authorization` уходит в capability report (D-016, D-035). Probes не создают событий.
- Не входят: Bluetooth, микрофон/речь, фоновая геолокация, геозоны, HealthKit, Core NFC, контакты/календарь/напоминания, локальная сеть, расширения, push.

### v0.2 — Контекст и действия

Единый набор из трёх функций; в Katana уходят только результаты, через существующую очередь событий (D-037, D-038). Никакого фонового слежения и скрытого удалённого выполнения: каждое действие — своей кнопкой, с предпросмотром и подтверждением; ссылки только открывают экраны.

**Activity Journal** (D-039)
- «Определить текущую активность» → одна категория (`stationary` / `walking` / `running` / `cycling` / `automotive` / `unknown`), уверенность и время проверки → «Отправить в Katana».
- Ручная сессия: «Начать сессию» → пока приложение открыто, считаются только длительности категорий → «Завершить» → предпросмотр агрегатов → «Отправить в Katana» или «Удалить без отправки». В фоне iOS не даёт приложению наблюдать — это время честно попадает в «неизвестно», и экран об этом говорит.
- После закрытия приложения сессия восстанавливается как «прервана»: её можно завершить или удалить.
- Не отправляются: сырые данные движения, временной ряд, координаты.

**Location Check-in** (D-040)
- «Определить текущее место» → (разрешение «При использовании», только сейчас) → предпросмотр: время, точность, выбор «Приблизительно» (≈1 км) / «Точно» → «Отправить в Katana» → подтверждение.
- Координаты — чувствительные данные: до подтверждения живут только в памяти (не дольше 5 минут), после отправки в очередь сразу стираются с экрана; в истории на iPhone координат нет.
- Нет фоновой геолокации, «Всегда», геозон и отслеживания перемещений.

**Локальные напоминания** (D-041, D-042)
- Katana открывает ссылку `katana-connector://open?v=2&feature=reminder&draft_id=<uuid>` — в ней нет текста, только непрозрачный идентификатор.
- Экран черновика → «Загрузить напоминание» (authenticated HTTPS) → пользователь видит заголовок, текст и время → «Создать напоминание» → только теперь при необходимости запрос разрешения на уведомления → одно локальное уведомление.
- Повторное открытие ссылки или повторный тап дубль не создают. Список «Локальные напоминания» показывает созданные Connector напоминания; любое можно отменить.
- В Katana уходят только факты «запланировано» / «отменено» — без заголовка и текста.

**История в Katana** — каждая функция показывает свои последние результаты и их статус («ждёт отправки» / «отправлено в Katana» / «Katana не приняла»); доставка — та же persistent-очередь со scope подключения, offline и перезапуск не теряют и не дублируют события.

### v0.3 — Физические триггеры и захват

Тот же принцип: ссылки только открывают экраны, всё чувствительное — по кнопке, с preview и подтверждением; события — через существующую очередь (D-045…D-053).

**Action Drafts** — Katana готовит действие (NFC-действие, геозону или запрос «поделиться»), ссылка `…v=3&feature=action&draft_id=<uuid>` открывает экран, «Загрузить действие» показывает, что будет сделано, «Выполнить» — делает. Повторно выполнить нельзя.

**NFC-действия** — действие от Katana можно повесить на NFC-метку через Команды (Shortcuts): касание → Connector показывает preview → «Выполнить» или «Отклонить». Никакой UID и содержимое метки не сохраняются. Нативное сканирование и запись меток (Core NFC) есть в коде, но в этой сборке выключено: нужен entitlement, который проверим отдельно (D-046).

**Геозоны** — «Определить текущее место» → имя и радиус → preview → «Зарегистрировать» → подтверждение → разрешение «Всегда» (только тут). При входе/выходе Katana получает только «вход/выход» и время, без координат. До 20 геозон, каждую можно выключить и удалить; Connector показывает реальное состояние iOS.

**Поделиться с Katana** — текст, ссылка, фото/изображение, PDF или текстовый файл → preview (тип, размер, имя только на экране) → «Отправить в Katana». У изображений удаляются EXIF и геоданные. В этой сборке — через экран в приложении; системный пункт «Поделиться → Katana Connector» (Share Extension) собран, но включится после проверки App Group на iPhone (D-046).

### Отложено (deferred)

Не реализуются, пока нет отдельного решения в `DECISIONS.md`:

- HealthKit
- Core NFC
- Фоновое отслеживание местоположения (UIBackgroundModes, significant-change) — геозоны v0.3 его не используют
- App extensions кроме Share Extension (Widget, Notification Service и т.п.); Share Extension и Core NFC — ждут проверки entitlements (D-046)
- Push-уведомления (APNs)
- Bluetooth (BLE)

Причины: требуют entitlements и платного аккаунта разработчика / не работают или работают ограниченно при установке через Sideloadly с бесплатным Apple ID; повышают требования к приватности и ревью.
